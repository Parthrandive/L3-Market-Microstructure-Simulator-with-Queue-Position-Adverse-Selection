# L3 Order Book & Microstructure Simulator

Oct 17, 2026 · @Parth

A 10-week project (Oct 19 – Dec 27, 2026) to build a C++20 L3 order book, replay real Nasdaq ITCH 5.0 data, and measure how much a naive backtester overstates fills compared to queue-aware and latency-aware execution models.

## Project Goal & Measured Numbers Rule

- **Goal:** Quantify the fill overstatement and adverse selection of naive "touch-fill" backtesting on real market data by comparing it against queue-aware and wire-latency-aware fill models.
- **Measured numbers only:** Publish only numbers directly generated by benchmarks and experiments run on this codebase. No hypothetical, unverified, or decorative metrics. If an effect shrinks or vanishes under testing, report the measured result as-is.
- **Scope of conclusions:** Results describe the specific passive strategy tested (e.g. posting at the best bid when order-book imbalance exceeds a threshold) on the selected symbols and dates, not a blanket law about all trading strategies or all backtesters.

## Definition of Done

### Stage 1 – Parser and Book
- Parses an ITCH 5.0 feed without dropping or misreading messages.
- Differential test: every $N$ messages, best bid/offer, level quantities, and order counts match a slower `std::map` reference book.
- Invariants hold throughout: no crossed book, no negative quantity, no leaked nodes in the pool.
- Zero heap allocation on the hot path (verified with a counting allocator or instrumentation).
- **Week 0 Fixture:** Filter from full ITCH data down to 3 symbols (AAPL, SPY, NVDA) using the stock-locate field while retaining all system-event ('S') and stock directory ('R') messages.
- **Node Layout:** `OrderNode` is exactly 32 bytes: order ref (8), price (4), quantity (4), next and prev indices (4 + 4), price-level index (4), side and flags. Verified by `static_assert(sizeof(OrderNode) == 32)`.
- **Order Lookup:** Pre-allocated open-addressed hash table (power-of-2 size, backward-shift deletion) instead of `std::unordered_map`.
- **Endianness:** Big-endian parsing via `memcpy` and `__builtin_bswap32/64` to maintain alignment and keep UBSan clean.

#### Stage 1 Verification Status (Passed)
- **Zero-Allocation Proof:** Overrode global `operator new` and `operator delete` with an atomic counter. Across the entire 4,115,178-message replay post-setup, hot-path allocations were measured at **0 operator-new calls during replay** (0 bytes / 0 allocations from engine code).
- **Queue-Order Parity Proof:** Replayed 4,115,178 messages across 17.01 hours (Dec 30, 2019) simultaneously through `OrderBook` (arena) and `ReferenceOrderBook` (`std::map`).
  - Best bid and best ask were asserted to match identically after **every single message update** (4,096,185 book updates).
  - Across 8,192 periodic snapshots and at EOD, each active price level's complete FIFO sequence of `order_ref`s was extracted and verified bit-for-bit identical with the reference queue.
  - End-of-day resting orders: exactly 0 across all 3 tickers (clean reconciliation).
  - Crossed books: 0 (`best_bid > best_ask`). Locked books: 0 (`best_bid == best_ask`). Missing lookups: 0.
- **64-Byte Cache-Line Alignment:** `Pool<T>` base storage allocated with 64-byte alignment (`posix_memalign`). For 32-byte `OrderNode`, index `2k` and `2k+1` are strictly packed into the same 64-byte L1 cache line (verified via runtime assertions and unit test).
- **Full-Day Replay Throughput (Apple M-series, single-core, Release build, 5 repeated runs):**
  - `ReferenceOrderBook`: Median **646.0 ms** (spread: 636 ms – 655 ms, ~6.37M msg/s).
  - `OrderBook` (Arena): Median **381.0 ms** (spread: 363 ms – 427 ms, ~10.80M msg/s).
  - End-to-end replay speedup, including gzip: **1.70×** (isolated book speedup measured in Stage 2 via mmap).
- **Sanitizers:** Clean under AddressSanitizer and UndefinedBehaviorSanitizer across all 24 unit tests and the full 4.1M-message replay.
- **Empirical Peaks (Dec 30, 2019):**
  - AAPL: 27,110 peak resting orders, 5,320 peak active price levels.
  - NVDA: 12,800 peak resting orders, 3,126 peak active price levels.
  - SPY: 1,949 peak resting orders, 756 peak active price levels.
  - Global simultaneous peak resting orders: 41,366.
- **OrderIdMap Performance (131,072 slots):**
  - Max probe length: 10 (AAPL), 7 (NVDA), 4 (SPY).
  - Average probes per insert: 1.01 (SPY), 1.09 (NVDA), 1.22 (AAPL).

### Stage 2 – Benchmarks (Completed & Verified)

  - **Reference Book Only:** Median **940.49 ms** (**4.38M msg/s**, ~228.5 ns/msg)
  - **Isolated Book Speedup:** **2.91×** (Total in-memory speedup: **2.72×**)
- **Zero-Allocation Verification on MMAP:** Exactly **0 heap allocations** across all 4,115,178 messages.
- **Pure Batch Latency (`Batch time / 64` on 24 MHz Apple Silicon clock, zero inner timers):**

- **Multi-Day Headroom Verification:**
  - Sized `OrderNodePool` to **131,072 nodes** (4 MB) and `OrderIdMap` to **262,144 slots** (load factor $\le 0.12$).

### Stage 3 – Queue Position and Latency (Completed & Verified)
*All numbers directly quoted from [STAGE3_REPORT.md](STAGE3_REPORT.md) (strictly regular hours 09:30–16:00 ET on Dec 30, 2019 and Oct 30, 2019).*

> **Definition:** *Naive touch fill is an execution simulation model that assumes a resting limit order fills immediately and in full upon the occurrence of any trade at or through its limit price, disregarding queue priority and resting depth ahead.*

- **Lock-Free SPSC Ring Buffer (`SpscRingBuffer`):**
  - Cache-line padded read/write indices (`alignas(128)`) to eliminate false sharing.
  - Verified under **ThreadSanitizer (TSan)** across 500,000 multi-threaded message transfers with **0 data races** and **0 dropped messages**.
- **Naive Touch Overstatement & Block-Bootstrapped Confidence Intervals:**
  - Dec 30, 2019 (Holiday lull, 1,827 orders, 459 true L3 fills):
    - True L3 Fill Rate: **25.12% [95% CI: 20.56% – 30.41%]**
    - Naive Touch Rate: **40.34% [95% CI: 34.51% – 47.88%]**
    - Overstatement Ratio: **1.61× [95% CI: 1.48× – 1.75×]**
  - Oct 30, 2019 (FOMC volatile session, 867 orders, 408 true L3 fills):
    - True L3 Fill Rate: **47.06% [95% CI: 39.76% – 52.16%]**
    - Naive Touch Rate: **61.13% [95% CI: 55.22% – 66.17%]**
    - Overstatement Ratio: **1.30× [95% CI: 1.22× – 1.44×]**
- **Wire Latency ($\Delta t$) Sweeps & Post-Fill Markout (Dec 30 Baseline):**
  - $\Delta t = 0\,\mu\text{s}$: 25.12% fill rate | +1.26 bps @ 1s | +1.42 bps @ 5s
  - $\Delta t = 50\,\mu\text{s}$: 23.83% fill rate | +1.24 bps @ 1s | +1.41 bps @ 5s
  - $\Delta t = 100\,\mu\text{s}$: 23.83% fill rate | +1.24 bps @ 1s | +1.41 bps @ 5s
  - $\Delta t = 250\,\mu\text{s}$: 23.83% fill rate | +1.24 bps @ 1s | +1.41 bps @ 5s
  - $\Delta t = 500\,\mu\text{s}$: 23.65% fill rate | +1.24 bps @ 1s | +1.40 bps @ 5s
- **Level-2 Queue Estimation Accuracy (Pessimistic vs. Probabilistic):**
  - Models barely differ (within 0.1 to 1.5 shares MAE) because executions overwhelmingly dominate depth depletion at the Best Bid. Relative MAE drops from 30.8% in shallow queues ($\le 200$ sh) to 2.9% in deep queues (>5k sh).
- **Multiple Testing Disclosure:** Full parameter matrix (1s, 5s, 10s TTL; OBI > 0.0 vs OBI > 0.20 vs unconditional) documented in `STAGE3_REPORT.md`. Naive touch overstatement reaches **2.93×** under fast 1s cancel horizons.

See [STAGE3_REPORT.md](STAGE3_REPORT.md) and [STAGE4_REPORT.md](STAGE4_REPORT.md) for complete experimental protocols, multi-day tables, and sensitivity sweeps.

### Stage 4 – Fill Simulator & Adverse Selection (Completed)
- Evaluated 3 fill models for a passive quote-posting strategy (100 shares @ Best Bid when $\text{OBI} > 0.0$, 5.0s TTL, 250 ms sampling rate; baseline chosen during Stage 3; full 18-combination grid reported) across Dec 30 (holiday lull) and Oct 30 (FOMC rate decision) sessions ($N > 64\text{k}$ orders/day):
  1. **Model 1: Naive Touch Fill:** Fills immediately and in full upon any trade at or through limit price.
  2. **Model 2: Queue-Aware L3 Fill ($\Delta t = 0\,\mu\text{s}$):** Fills only when depth ahead (preceding shares in FIFO queue plus own shares) is consumed by true intrusive executions on pure order book state.
  3. **Model 3: Latency-Aware L3 Fill ($\Delta t \in \{50\,\mu\text{s}, 100\,\mu\text{s}, 250\,\mu\text{s}, 500\,\mu\text{s}\}$):** Incorporates wire transit delay.
- **Empirical Findings Summary (95% Time-Block Bootstrap CI across 64k+ orders/day):**
  - **Fill Rate Overstatement:** On the 5s TTL baseline, Naive touch overstates full fill rates by **1.40× [95% CI: 1.36× – 1.45×]** on Dec 30 (46.72% vs 33.31%) and **1.43× [95% CI: 1.38× – 1.48×]** on Oct 30 (44.58% vs 31.20%).
  - **Overstatement Range across TTLs & Sizes:** Overstatement ranges from **~1.10× at 30s TTL** to **2.25×–2.45× at 1s TTL** for 100 shares, and reaches **7.5×–8.8× at 1s TTL** (and **3.2×–3.5× at 5s TTL**) for 500 shares.
  - **First-Fill vs. Full-Fill Dynamics:** For 500-share orders, while first-fill rate remains identical to 100-share orders (~38%–41%, since first fill occurs at the same queue depth), full-fill rate collapses to **14.76% (Dec 30) and 12.94% (Oct 30)** because exhausting 500 shares requires substantial subsequent execution volume before TTL expiration.
  - **Premature Execution Lead Time:** Touch fills trigger **485.3 ms [95% CI: 463.9 – 508.6 ms]** (Dec 30) and **490.5 ms [95% CI: 455.3 – 525.2 ms]** (Oct 30) before real queue depletion.
  - **Convergence at 30s:** At 30s, net markouts for both models converge (-0.26 bps vs -0.49 bps on Dec 30; -0.17 bps vs -0.34 bps on Oct 30) with bootstrap confidence intervals spanning across broader spreads, showing no statistically significant sign inversion.
  - **Wire Latency Null Result:** Sweeping $\Delta t \in [0, 500\,\mu\text{s}]$ changes fill rate by <0.1% and markout PnL by <0.5%, showing wire transit delay has a negligible effect compared to queue priority itself.
  - **Comprehensive Multiple-Testing Disclosure:** Full Cartesian grid across 18 parameter combinations (100/500 shares, 1s/5s/30s TTL, unconditional/OBI>0/OBI>0.20) disclosed in [STAGE4_REPORT.md](STAGE4_REPORT.md). Unconditional order counts are strictly invariant to TTL (82,173 on Dec 30; 79,686 on Oct 30); OBI order counts are strictly invariant to order size (67,432 on Dec 30; 64,102 on Oct 30).
  - **Speedup Verification:** Both Google Benchmark (**2.21× speedup**, macro replay including decode) and custom harness (**2.60× speedup**, engine-only) are verified and reported.

See [STAGE4_REPORT.md](STAGE4_REPORT.md) for full experimental tables, bootstrap distributions, cross-stage technical reconciliation, and sensitivity sweeps.

## Experimental Integrity & Rules

- **Data:** Validated against public Nasdaq TotalView-ITCH 5.0 data (Dec 30, 2019 and Oct 30, 2019).
- **Strict reporting:** No fabricated metrics in reports. All values reflect measured experimental output from reproducible code and fixtures.
- **Benchmark attribution:** Google Benchmark (`l3_benchmarks`) measures macro throughput and spread across 10 randomly interleaved repetitions (2.21× speedup); custom harness (`bench_stage2`) measures engine-only throughput (2.60× speedup) and batch distributions (mean, p50, p90, p99, p99.9).
- **Distinction of latencies:**
  - *Simulated wire latency ($\Delta t$):* A configurable model input parameter representing transit time.
  - *Engine processing latency:* Measured execution time per message.
- **Node layout:** 32-byte `OrderNode` using 32-bit indices packed into 64-byte aligned pools (zero hot-path heap allocation).
- **Hardware environment:** Apple Silicon M1 (24 MHz hardware timebase, unpinned Darwin thread scheduling).
