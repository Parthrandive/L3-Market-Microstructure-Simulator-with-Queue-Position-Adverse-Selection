# L3 Order Book & Microstructure Simulator

Oct 17, 2026 · @Parth

A 10-week project (Oct 19 – Dec 27, 2026) to build a C++20 L3 order book, replay real Nasdaq ITCH 5.0 data, and measure how much a naive backtester overstates fills compared to queue-aware and latency-aware execution models.

## Project Goal & Measured Numbers Rule

- **Goal:** Quantify the fill overstatement and adverse selection of naive "touch-fill" backtesting on real market data by comparing it against queue-aware and wire-latency-aware fill models.
- **Measured numbers only:** Publish only numbers directly generated by benchmarks and experiments run on this codebase. No hypothetical, unverified, or decorative metrics. If an effect shrinks or vanishes under testing, report the measured result as-is.
- **Scope of conclusions:** Results describe the specific passive strategy tested (e.g. posting at the best bid when order-book imbalance exceeds a threshold) on the selected symbols and dates, not a blanket law about all trading strategies or all backtesters.

## Definition of Done

### Stage 1 – Parser and Book
- Parses an ITCH 5.0 feed without dropping or misreading messages.
- Differential test: every $N$ messages, best bid/offer, level quantities, and order counts match a slower `std::map` reference book.
- Invariants hold throughout: no crossed book, no negative quantity, no leaked nodes in the pool.
- Zero heap allocation on the hot path (verified with a counting allocator or instrumentation).
- **Week 0 Fixture:** Filter from full ITCH data down to 3 symbols (AAPL, SPY, NVDA) using the stock-locate field while retaining all system-event ('S') and stock directory ('R') messages.
- **Node Layout:** `OrderNode` is exactly 32 bytes: order ref (8), price (4), quantity (4), next and prev indices (4 + 4), price-level index (4), side and flags. Verified by `static_assert(sizeof(OrderNode) == 32)`.
- **Order Lookup:** Pre-allocated open-addressed hash table (power-of-2 size, backward-shift deletion) instead of `std::unordered_map`.
- **Endianness:** Big-endian parsing via `memcpy` and `__builtin_bswap32/64` to maintain alignment and keep UBSan clean.

#### Stage 1 Verification Status (Passed)
- **Zero-Allocation Proof:** Overrode global `operator new` and `operator delete` with an atomic counter. Across the entire 4,115,178-message replay post-setup, hot-path allocations were measured at **0 operator-new calls during replay** (0 bytes / 0 allocations from engine code).
- **Queue-Order Parity Proof:** Replayed 4,115,178 messages across 17.01 hours (Dec 30, 2019) simultaneously through `OrderBook` (arena) and `ReferenceOrderBook` (`std::map`).
  - Best bid and best ask were asserted to match identically after **every single message update** (4,096,185 book updates).
  - Across 8,192 periodic snapshots and at EOD, each active price level's complete FIFO sequence of `order_ref`s was extracted and verified bit-for-bit identical with the reference queue.
  - End-of-day resting orders: exactly 0 across all 3 tickers (clean reconciliation).
  - Crossed books: 0 (`best_bid > best_ask`). Locked books: 0 (`best_bid == best_ask`). Missing lookups: 0.
- **64-Byte Cache-Line Alignment:** `Pool<T>` base storage allocated with 64-byte alignment (`posix_memalign`). For 32-byte `OrderNode`, index `2k` and `2k+1` are strictly packed into the same 64-byte L1 cache line (verified via runtime assertions and unit test).
- **Full-Day Replay Throughput (Apple M-series, single-core, Release build, 5 repeated runs):**
  - `ReferenceOrderBook`: Median **646.0 ms** (spread: 636 ms – 655 ms, ~6.37M msg/s).
  - `OrderBook` (Arena): Median **381.0 ms** (spread: 363 ms – 427 ms, ~10.80M msg/s).
  - End-to-end replay speedup, including gzip: **1.70×** (isolated book speedup measured in Stage 2 via mmap).
- **Sanitizers:** Clean under AddressSanitizer and UndefinedBehaviorSanitizer across all 24 unit tests and the full 4.1M-message replay.
- **Empirical Peaks (Dec 30, 2019):**
  - AAPL: 27,110 peak resting orders, 5,320 peak active price levels.
  - NVDA: 12,800 peak resting orders, 3,126 peak active price levels.
  - SPY: 1,949 peak resting orders, 756 peak active price levels.
  - Global simultaneous peak resting orders: 41,366.
- **OrderIdMap Performance (131,072 slots):**
  - Max probe length: 10 (AAPL), 7 (NVDA), 4 (SPY).
  - Average probes per insert: 1.01 (SPY), 1.09 (NVDA), 1.22 (AAPL).

### Stage 2 – Benchmarks (Completed & Verified)
*All numbers directly quoted from [BENCHMARKS.md](BENCHMARKS.md) (measured on Apple Silicon arm64, single-core, AppleClang 17.0.0, `-O3 -DNDEBUG`).*

- **MMAP Replay Throughput (10 Runs post-warmup, no I/O, no zlib):**
  - **Decode Only:** Median **22.16 ms** (**185.71M msg/s**, 5.38 ns/msg)
  - **Arena Book Only:** Median **179.89 ms** (**22.88M msg/s**, 43.7 ns/msg)
  - **Reference Book Only:** Median **468.12 ms** (**8.79M msg/s**, 113.8 ns/msg)
  - **Isolated Book Speedup:** **2.60×** (Total in-memory speedup: **2.43×**)
- **Zero-Allocation Verification on MMAP:** Exactly **0 heap allocations** across all 4,115,178 messages.
- **Batch Latency (`Batch time / 64` on 24 MHz Apple Silicon clock):**
  - p50: **72.3 ns/msg** | p90: **97.7 ns/msg** | p99: **181.0 ns/msg** | p99.9: **819.7 ns/msg**
- **Tail Attribution by Operation & Level Mutation:**
  - Adding to an existing level: p50 = 42 ns, p99.9 = **375 ns**
  - Creating a new price level (8-byte `LevelRef` vector insert): p50 = 83 ns, p99.9 = **625 ns** (~250 ns tail contribution)
- **Multi-Day Headroom Verification:**
  - Replayed both holiday-lull (`12302019`) and FOMC rate decision (`10302019`) sessions.
  - Largest measured resting peak: **30,483** orders (AAPL on FOMC day), utilizing 46.51% of the 65,536 pool ($>2.1\times$ margin).
  - Both sessions passed 100% full-day differential parity with bit-for-bit identical FIFO queue sequences.

See [BENCHMARKS.md](BENCHMARKS.md) for full run protocols, sample distributions, and hardware specifications.

### Stage 3 – Queue Position and Latency
- Lock-free SPSC ring buffer between the feed reader and the book thread, verified under TSan.
- Two queue models: pessimistic (cancels ahead do not advance position) and probabilistic (cancels ahead distributed across queue).
- Measure error of L2 queue estimation models against ground truth L3 queue position from ITCH.
- Simulated wire-to-wire delay ($\Delta t$) kept strictly separate from measured engine processing latency.

### Stage 4 – Fill Simulator & Adverse Selection
- Compare 3 fill models for a fixed passive strategy (e.g. joining the best bid when OBI is favorable):
  1. Naive touch fill (fills immediately when trade occurs at limit price).
  2. Queue-aware fill (fills only when depth ahead is depleted by executions).
  3. Queue-aware fill with wire latency $\Delta t$.
- Post-fill markout of mid-price at 1s, 5s, and 30s to evaluate adverse selection.
- Output: A comparative summary table showing fill rate, post-fill markout, and strategy PnL across models.

### Stage 5 – Python Bridge
- `nanobind` module exposing order submission, cancellation, and callbacks.
- Replay test agent interacting with simulator.

## Experimental Integrity & Rules

- **Data:** Validated against public Nasdaq TotalView-ITCH 5.0 data.
- **Strict reporting:** No fabricated metrics in reports. Any table layouts in early drafts are structural placeholders; final values reflect measured experimental output only.
- **Distinction of latencies:**
  - *Simulated wire latency ($\Delta t$):* A configurable model input parameter representing transit time.
  - *Engine processing latency:* Measured execution time per message.
- **Node layout:** 32-byte `OrderNode` using 32-bit indices rather than 64-bit pointers.
- **Hardware counters:** Linux `perf` or macOS Instruments reported with environment details.
